# 4Seasons — نظام المغسلة (الموقع + الكاشير + قاعدة البيانات)

نظام واحد بيجمع:

| الرابط | الوصف |
|---|---|
| `/` | الموقع العام للعملاء. الأسعار والتليفونات بتتقرأ من قاعدة البيانات، ونموذج «اطلب خدمة» بيسجّل الطلب مباشرة في النظام |
| `/app` | نظام الكاشير والإدارة (دخول بحساب لكل موظف) |
| `/api` | الواجهة البرمجية (REST) اللي الاتنين بيستخدموها |

قاعدة البيانات: **SQLite** (ملف واحد، وضع WAL) — مجرّبة على **50 ألف عميل و200 ألف طلب** (حجم الملف ≈ 145MB) والقوائم الأساسية بترد في أقل من 0.4 ثانية.

## التشغيل

المطلوب: **Node.js 22.13 أو أحدث** (بيستخدم SQLite المدمج، مفيش قاعدة بيانات خارجية تتثبّت).

```bash
npm install
npm start
```

أول تشغيل بيعمل تلقائيًا: إنشاء قاعدة البيانات، الخدمات والأسعار، المناطق، وحساب مدير:

```
المستخدم: admin
كلمة المرور المؤقتة: (بتظهر في الشاشة وبتتحفظ في data/FIRST_RUN_CREDENTIALS.txt)
```

أول ما تدخل هيطلب منك تغيير كلمة المرور. **امسح ملف FIRST_RUN_CREDENTIALS.txt بعدها.**

افتح `http://localhost:3000/app` للنظام، و`http://localhost:3000/` للموقع.

## صور الموقع (مطلوبة)

حط الصورتين دول في `website/assets/` بنفس الاسم:

- `4seasons-logo.jpg` — الشعار
- `laundry-services-collage.png` — صورة الكولاج (4 مربعات: ملابس / سجاد / مفروشات / ستائر)

لو الشعار مش موجود الموقع بيخفيه تلقائيًا من غير ما يبوّظ الشكل.

## الأدوار والصلاحيات

| الدور | يقدر |
|---|---|
| مدير | كل حاجة: الأسعار، المناطق، بيانات الموقع، المستخدمين، النسخ الاحتياطي، سجل العمليات |
| كاشير | العملاء، إنشاء الطلبات، القياس/التسعير، تغيير حالة الطلب، التحصيل، طلبات الموقع |
| محاسب | مشاهدة الطلبات والمؤشرات فقط |

**صلاحيات مخصصة لكل موظف:** من الإعدادات ← المستخدمون ← «إضافة مستخدم» المدير يكتب اليوزر والاسم، ويقدر يحدد كلمة المرور بنفسه (أو تتولّد مؤقتة)، ويختار بالتفصيل اللي يقدر يعمله (الرئيسية، العملاء، الطلبات، التحصيل، طلبات الموقع). زرار «الصلاحيات» جنب كل موظف يعدّلها في أي وقت وتسري فورًا، و«رجوع لصلاحيات الدور» يرجّعها للافتراضي. الإعدادات وإدارة المستخدمين للمدير فقط ومش بتتمنح. (يحتاج مايجريشن `004_user_permissions.sql`.)

إنشاء مستخدم من الشاشة: الإعدادات ← المستخدمون. أو من الطرفية:

```bash
node server/cli.js create-user --username sara --name "سارة" --role cashier
node server/cli.js reset-password --username sara
node server/cli.js list-users
```

## تحكم المدير والرسائل والموبايل

- **تحكم المدير اليدوي** (للمدير فقط): زرار «تحكم» في جدول الطلبات يعدّل الحالة والإجمالي والمدفوع وتاريخ الطلب والميعاد والملاحظة أو يحذف الطلب. وفي جدول العملاء يعدّل المديونية السابقة، ويحذف أي دفعة، ويحذف العميل (مع طلباته بعد تأكيد مزدوج). كل ده بيتسجل في سجل العمليات (`admin.*`).
- **الرسائل الداخلية:** قائمة «الرسائل» لكل المستخدمين (وارد/صادر، شارة غير مقروء، ردود في سلسلة، رسالة للكل). الحد 30 رسالة/ساعة للمستخدم.
- **القائمة الجانبية:** زرار فوق يفتحها ويقفلها (على الكمبيوتر بتتقلص لأيقونات وبتفتكر اختيارك، وعلى التليفون بتظهر كدرج).
- **على التليفون:** افتح `/app` من متصفح التليفون ← «إضافة إلى الشاشة الرئيسية» وهيشتغل كتطبيق (فيه أيقونة وmanifest).
- مايجريشن جديدة: `005_clothes_prices.sql` (أسعار الملابس) و`006_messages.sql`.

## الموظفون والمرتبات (للمدير فقط)

قائمة «الموظفون والمرتبات» تظهر للمدير فقط. صلاحية `hr:manage` **غير قابلة للمنح**: مش موجودة في شاشة الصلاحيات، فمستحيل كاشير أو محاسب يشوفها أو يستدعي الـ API بتاعها (بيرجع 403)، حتى لو اتعدّلت صلاحياته يدويًا.

| التبويب | اللي المدير بيتحكم فيه |
|---|---|
| الموظفون | الاسم، الوظيفة، نوع الأجر (شهري / بالساعة)، المرتب أو أجر الساعة، **ساعات العمل اليومية**، **حد السلف** الخاص بالموظف، رصيد الإجازة، التفعيل والتعطيل |
| الحضور وساعات العمل | تسجيل الساعات الفعلية لكل موظف يوميًا (زرار «تعبئة الساعات المعتادة»)، وسجل شهري لكل موظف بالإضافي |
| الإجازات | سنوية (تُخصم من الرصيد وتُرفض لو الرصيد مش كفاية)، مرضية، أخرى بمرتب، **بدون مرتب** (تُخصم تلقائيًا من المرتب). الإجازة الأسبوعية (الجمعة افتراضيًا) مش بتتحسب |
| الخصومات والمكافآت | خصم أو مكافأة بمبلغ وسبب وتاريخ، بتدخل في مرتب الشهر اللي تاريخها فيه |
| السلف | صرف سلفة (بتتعمل رفض لو تعدّت حد السلف)، قسط شهري اختياري بيتخصم تلقائيًا من المرتب، سداد يدوي، ومتابعة المتبقي |
| كشف المرتبات | حساب تلقائي لأي شهر، ثم «اعتماد وصرف» بيثبّت الأرقام ويقفل الشهر للموظف. «إلغاء» بيحذف الكشف ويرجّع أقساط السلف |
| قواعد الحساب | أيام العمل في الشهر، ساعات اليوم الافتراضية، معامل الساعة الإضافية، حد السلف الافتراضي (٪ من المرتب)، رصيد الإجازة الافتراضي، الإجازة الأسبوعية |

**معادلة المرتب:** `الصافي = الأساسي + الإضافي + المكافآت − الخصومات − الغياب بدون مرتب − أقساط السلف`

- الموظف الشهري: أجر الساعة = المرتب ÷ (أيام العمل × ساعات اليوم). الساعات اللي فوق ساعات اليوم = إضافي × المعامل. أجر اليوم = المرتب ÷ أيام العمل.
- الموظف بالساعة: الأساسي = إجمالي الساعات المسجلة × أجر الساعة.
- حد السلف = المبلغ المخصص للموظف، أو (النسبة الافتراضية × مرتبه الشهري) لو مفيش تخصيص. المستحق + السلفة الجديدة لازم ما يتعداش الحد.
- أقساط السلف ما بتخليش الصافي يبقى بالسالب (بتتخصم في حدود المتاح فقط).
- كل عملية (إضافة موظف، تغيير مرتب، سلفة، خصم، إجازة، اعتماد مرتبات…) بتتسجل في سجل العمليات `hr.*`.
- يحتاج المايجريشن `007_hr.sql` (بيتطبّق تلقائيًا عند التشغيل، ومش بيمس البيانات الحالية). الكود في `server/hr.js` و`app/hr.js`، واختباراته في `test/hr.test.js`.

## الربط بين الموقع والكاشير

1. العميل يملأ نموذج الموقع ← بيتسجل في `web_requests` (مع حماية من الروبوتات والتكرار).
2. يظهر عند الكاشير في «طلبات الموقع» برقم أحمر على القائمة.
3. زرار «تحويل لطلب» بينشئ العميل (أو يلاقيه برقم الموبايل) ويفتح الكاشير جاهز لإضافة الخدمات.
4. أي تعديل في الأسعار أو الأرقام من الإعدادات يظهر في الموقع فورًا.

### عميل جديد / عميل سابق

نموذج الموقع فيه اختيار **عميل جديد** (الاسم والهاتف والعنوان) و**عميل سابق**:

- **بالكود** (مثال `4S-C-000124`): العميل بيكتب الكود + آخر 4 أرقام من تليفونه المسجّل.
- **نسي الكود**: بيكتب رقم تليفونه ← الموقع بيعرض اسم/رقم مُخفّى جزئيًا فقط ← بيطلب **كود تحقق (6 أرقام)**.
  الكود بيظهر للكاشير في أعلى «طلبات الموقع» وبزر «إرسال على واتساب» يبعته لرقم العميل المسجّل. لو ضبطت `OTP_WEBHOOK_URL` بيتبعت تلقائيًا.
- بعد التحقق بيشوف بياناته (الكود، الاسم، الهاتف، العنوان، المستحق، آخر 5 طلبات) ويقدر **يعدّل الاسم والهاتف والعنوان** — كل تعديل بيتسجل في سجل العمليات.
- بعدها يختار الخدمة ويرسل؛ الطلب بيتربط بنفس العميل (علامة «سابق» + الكود في جدول الطلبات)، ويقدر يبعت حتى 3 طلبات مفتوحة في نفس الوقت (العميل الجديد لسه ليه طلب مفتوح واحد/24 ساعة).
- الأمان: توكن موقّع 30 دقيقة بيتحفظ في الذاكرة فقط، كود صالح 10 دقايق و5 محاولات، حد 3 أكواد/ساعة، قفل 15 دقيقة بعد 5 محاولات غلط، وحد معدل لكل IP.
- الموقع لو على دومين مختلف: ضيفه في `PUBLIC_ORIGINS` وغيّر ثابت `API` في `website/site.js` لعنوان السيرفر.
- يحتاج المايجريشن `server/migrations/003_returning_customers.sql` (بيتطبّق تلقائيًا عند التشغيل).

## النسخ الاحتياطي

- نسخة تلقائية يوميًا في `data/backups` (بيحتفظ بآخر 14).
- من الشاشة: الإعدادات ← النسخ الاحتياطي والسجل ← تنزيل.
- من الطرفية: `node server/cli.js backup`.
- الاستعادة: أوقف السيرفر وانسخ ملف النسخة مكان `data/4seasons.db`.

## النشر (Deploy)

- محتاج استضافة بتشغّل Node 22.13+ **وديسك دائم** للمجلد `data/` (VPS، Railway/Fly.io مع Volume، إلخ). الاستضافات اللي بتمسح الملفات عند كل تشغيل (مثل خطة Render المجانية) **مش مناسبة**.
- شغّله خلف HTTPS (Nginx أو Caddy أو Cloudflare) وحط `TRUST_PROXY=true`. الكوكي بتتأمّن تلقائيًا مع HTTPS.
- لو الموقع العام على دومين تاني: `PUBLIC_ORIGINS=https://دومينك` وغيّر العنوان في `website/site.js` (`/api/public/requests` ← الرابط الكامل).
- متغيرات البيئة كلها في `.env.example`.

## الأمان (اللي اتعمل)

- كلمات المرور scrypt، جلسات بتوكن عشوائي (محفوظ مشفّر في القاعدة)، كوكي `HttpOnly` + `SameSite=Strict`، قفل مؤقت بعد 5 محاولات فاشلة، وحد أقصى لمعدل الطلبات.
- كل الأسعار والإجماليات بتتحسب **على السيرفر** من الكتالوج (العميل مش بيقدر يتلاعب بالأسعار)، ومبالغ بالقروش كأعداد صحيحة.
- فحص `Origin` ضد CSRF، رؤوس CSP وأمان، تهريب كل مدخلات الصفحة العامة، سجل عمليات (Audit) لكل تعديل مهم.
- الفواتير القديمة بتحتفظ بالأسعار وقت إنشائها حتى لو الأسعار اتغيّرت (وتاريخ تغيير الأسعار محفوظ).

## الاختبارات

```bash
npm test                      # اختبارات الـ API (أسعار، صلاحيات، تحصيل، CSRF، قفل الحساب، والعميل السابق/OTP)
node server/cli.js seed-demo --customers 50000 --orders 200000   # بيانات ضخمة لتجربة الأداء (على قاعدة تجريبية!)
```

> ⚠️ `seed-demo` بيضيف بيانات وهمية — استخدمه على نسخة تجريبية فقط (`DB_PATH=/tmp/test.db`).

## لو العمل كبر أكتر

SQLite بتكفي لمغسلة (أو عدة فروع) لسنين. لو احتجت أكتر من سيرفر أو تقارير ثقيلة، البنية جاهزة للنقل إلى PostgreSQL (المخطط في `server/migrations`، وكل الاستعلامات في `server/domain.js`). البحث النصي في الطلبات (بالاسم/القطع) على 200 ألف طلب بياخد ~1 ثانية؛ ممكن تسرّعه بـ FTS5 لو احتجت.
